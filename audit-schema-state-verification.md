## Top Lines (highest priority)

1. Schema commit lock has no post-startup stale-lock recovery (schema/controller.ts:836-850) — one mid-commit crash wedges every future schema commit (F1).
2. Schema commit applies the workspace+generation first and treats its state.transition as optional (schema/controller.ts:430-499) — commits can leave the state head diverged from the committed workspace (F2).
3. state.verify conflates persistence/reporting failures with evidence violations and records a durable violation + revokes the current certificate (state/store.ts:1553-1568).
4. file_exists evidence never asserts existence (schema/controller.ts:651-657) — the primitive is inverted and fragile.
5. Postconditions may run mutating trusted_commands that sit OUTSIDE assertNoOutsideDrift (controller.ts:416-419 vs 754-765); re-check the fingerprint after postconditions or forbid mutating postconditions.
