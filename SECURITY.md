# Security

Report vulnerabilities privately to the repository maintainers.

The checked guest has no operating-system authority, timer API, or direct network path. Source is strictly type-checked in a bounded compiler worker and executes only in QuickJS. Provider calls are schema-validated, quota-bounded, cancellation-aware, and approval-gated before invocation. Configured network calls require network approval; configured stdio servers require a separate execute approval before process start. MCP authority comes only from the private `mcp.json` with `imports: []`; ambient editor servers and mcporter behavior-changing environment options are rejected, and the loaded server set is configuration-digest/provenance-bound.

Workspace persistence is canonical-filesystem-identity-bound, private, atomically replaced, and cross-process mutation-serialized. Ambiguous roots, absent elicitation support, changed workspace identity, malformed or over-budget persistence, non-private configuration, package aliases, unknown export destinations, stale release evidence, and unsupported artifact-root entries fail closed.

The release package contains no session wrapper, custom-agent selector, extension-host adapter, or generic MCP discovery surface. Ordinary build, test, local staging, hermetic certification, packaging, and release-report commands are guarded against `$KIRO_HOME` mutation. The explicit `power:stage` developer command installs owned source and active packages under `$KIRO_HOME/powers`, normalizes only a digest-bound Kiro-copied package carrying this installer's ownership marker, and atomically updates the bounded local `user-added` and installed-Power registries; run it with Kiro sessions closed. `power:stage:local` retains hermetic checkout-local behavior. The explicit real-client release gate uses operator-owned Kiro state but confines requested native file and shell probes to a private empty temporary working directory.
