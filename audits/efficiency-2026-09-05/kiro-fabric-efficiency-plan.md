## Kiro/provider and audit-harness constraints (not Fabric fixes)

1. **Routing prerequisite (B01):** model catalog and returned requested-model summary are insufficient. Repair/diagnose owner/child provider loading in the existing audit harness separately, without adding Pi to kiro-fabric. A bounded future route check must inspect terminal response provider/model and effective supported reasoning before dispatch. Current GLM phase remains unperformed. No more paid audit retries authorized by this plan.
2. **Installed Kiro qualification (B02):** provision access separately, no automatic installs/upgrades/settings changes. Record exact executable/version/help/auth mode/profile/commit. Use `scripts/run-kiro-agent-real-driver.mjs` and `scripts/real-client-evidence.mjs` with operator-approved budget. Don't assume README's historical client version or CLI syntax works elsewhere.
3. **Full compaction assertions:** before inference, define fixture facts for user constraints, decisions, unresolved questions, failed approaches, files/artifacts, finished/pending work and approval requirements. At least two real compactions, manual/automatic as supported; inspect pairing and incomplete effects. Random sentinel recall is necessary but insufficient. Summaries live with Kiro; artifacts aren't durable summaries. Never reuse historical approvals.
4. **Complete lifecycle observations:** retain timestamped MCP PID+instance+start, startup count, runtime generation, workspace identity, host session and worker/task IDs through ordinary turns, compaction, new/same-process resume where supported, explicit session, crash, workspace switch/concurrency, cancellation and TTL. Confirm old effects settle before replacement. Do not share private MCP runtimes between unrelated sessions to save startup cost.
5. **Billing:** obtain dated authoritative rules for actual account/plan and original usage fields; reconcile charged errors/retries/summary/validation with request IDs. Separate Kiro credits, Zro provider currency, other charges and audit overhead. Subscription allocation must be optional/labeled; marginal charges separate. Balance deltas invalid when delayed billing/unrelated activity cannot be separated. Unknown stays null.

## Future bounded benchmark protocol

No paid benchmark was run. This plan is not authorization for a sweep. Without an explicit live-benchmark cap, at most one baseline/candidate pilot; label preliminary. Route failures consume attempts; don't silently substitute models.

- Fixed fixtures/model/provider/supported reasoning/output limits/approvals/success assertions. Baseline first unmodified commit; individual isolated candidates before combination. Keep full failed trajectories and audit/validator inference costs separate.
- Workloads: cold + repeated warm capability; large result + recoverable failure; ≥2 compactions with full constraint ledger; new-host resume + interrupted checkpoint; concurrent workspaces, cancellation and TTL; bounded native worker failure/retry with no duplicated completed work. Mark unsupported cells, never simulate them and claim live results.
- Capture per request/run/parent/task timestamp, actual provider/model, original tokens/cache/reasoning usage, request count, latency, retries/cancellations/compactions and billed cost. Collect pre/post compaction size and subsequent recovery calls. Hash/bound references instead of copying private transcripts.
- Primary economic gate: total comparable cost across **all** attempts divided by successes; undefined at zero successes. Report success rate and latency jointly, tokens/credits separately. No fixed savings target before baseline. No reduction accepted if capability/correctness/approvals/isolation/recovery regress.
- Separate cold/warm prompt and application caches; fixed stable prefixes where safe, no stale permission caches. Counterbalance run order/repeat only within explicit cap, report n and dispersion. A single pilot cannot establish robust savings or quality equivalence.

## Must remain unchanged
