# Security model

Fabric Lite v1 runs trusted local model-generated programs in a disposable Node process. It is **not a sandbox for hostile JavaScript**. Imports and documented Node entry points are rejected, but Node isolation is not claimed.

Host capabilities contain paths under the real project root, reject traversal and symlink escape, deny secrets and common metadata/dependency/build trees, and cap reads. Writes are disabled by default. A single-agent permission model classifies every non-read operation into commit, execute, network, and destructive categories, each with a policy: read allows, commit/execute/network ask, and destructive denies (ask/allow can never override it). Ask policies are resolved by a prompter showing an exact action/args preview before the operation runs; interactive runs offer Allow once / Allow session / Deny and serialize prompts one-at-a-time; Allow session authorizes the whole selected permission category for the gate lifetime, not only the displayed action, while headless runs fail closed and deny. Authorization is deterministic and default-deny: only configured host policy and allowlists authorize an operation; model output, recommendations, confidence, or claimed urgency cannot authorize it. Enabling generic shell requires real human approval or an explicit project allowlist and still uses bounded streams, filtered environment, contained cwd, timeout, and process-group termination. Destructive commands are always denied even when policy otherwise permits execute. Kiro workers have no tools. Child AI calls receive a filtered authentication environment. A fixed versioned envelope separates authoritative operational instructions from untrusted context/schema, which cannot override the worker role. Before Kiro, repair, returned string data, and applicable diagnostics, deterministic high-confidence filters redact credentials, authorization values, private keys, and large media using per-request class/ordinal placeholders. Placeholders contain no value-derived hash. UUIDs and ordinary tokens are intentionally not blanket-redacted. Original matched values are never logged.

Local Git commits are independently gated by `git.allowCommit`, must name explicit safe paths plus a bounded single-line message, and additionally require commit approval (the commit permission, `ask` by default). Commit hooks, signing, attributes filters, and shell execution are bypassed. Fabric Lite exposes no push API; generic shell remains separately default-deny and network actions are not exposed.\n\nDedicated inspection methods provide bounded reads for PostgreSQL, Redis, SQLite, Kubernetes, and Terraform without exposing their mutation command surfaces. PostgreSQL runs one filtered statement inside a read-only transaction; SQLite opens a project-contained database in read-only safe mode; Redis and operational CLIs use fixed operation allowlists. Kubernetes secrets and known PostgreSQL operational functions are denied. These controls reduce risk but do not turn untrusted database extensions, servers, providers, or CLIs into a sandbox. Use least-privilege read-only credentials. Mutations require a separate explicit policy gate and user approval.

Security findings use this advisory escalation rubric: critical for observed credential disclosure, arbitrary command execution, or writes outside the authorized root; high for an observed default-deny bypass, path escape, or authorization-boundary crossing; medium for a bounded confidentiality or integrity weakness; low for defense-in-depth or documentation gaps. Unconfirmed impact remains explicitly unverified. This rubric prioritizes review and response only; it never grants authorization or changes deterministic enforcement.

Run artifacts contain trusted-local program source, program hashes, sizes, timing, metrics, model attribution, and final results. Requested and resolved model IDs are separate; resolution is unknown unless tested machine-readable Kiro metadata provides it. Fusion is never inferred from requested IDs. Full child prompts/transcripts are not retained. `.fabric-lite/runs/` is ignored. Treat run artifacts as potentially source-sensitive: deterministic filtering reduces accidental credential exposure but is not a general data-loss-prevention system. The trusted-local Node warning remains fundamental.
