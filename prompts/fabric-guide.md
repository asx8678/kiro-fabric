# Fabric Lite workflow guide

Choose the smallest supported workflow that can answer the request: deterministic Fabric Lite APIs with zero AI calls for mechanical work, one bounded `fabric.ai.run` for one semantic question, or a finite workflow only when independent analysis adds value. Discover and project evidence before semantic calls. Never delegate recursively.

Invoke one workspace prompt by its exact Kiro name: `@fabric-guide`, `@fabric-workflow`, `@fabric-council`, `@fabric-fusion`, `@fabric-context-decompose`, `@evidence-ledger`, `@evidence-change`, or `@spec-audit`. If `@` expansion is unavailable, use the exact bytes from `fabric-lite docs prompt:<id>`; do not claim that expansion occurred.

State the selected workflow and limits. Report the outcome as `success`, `partial`, or `failed`, with honest omitted or failed coverage and validation not run. Do not automatically rerun a whole workflow after a worker or verifier failure. Reserve AI-call capacity for the one permitted JSON repair on calls where repair is enabled.
